# Splits — frozen, do not regenerate

Generated by `../scripts/make_splits.py` (seed 42). Full statistics in `split_report.json`.

**Every experiment reports on `peptide_split`.** If you think the split is wrong, open an experiment
arguing that — do not quietly make your own. Numbers from different splits cannot be compared, and
the brief judges us on exactly this kind of discipline.

## How to use

```python
import pandas as pd

df = pd.read_csv("context/dataset.csv")
sp = pd.read_csv("splits/peptide_split.csv")        # peptide, cluster_id, split
df = df.merge(sp, on="peptide")                      # adds a `split` column

train = df[df.split == "train"]                      # 22,532 rows
val   = df[df.split == "val"]                        #  2,817 rows
test  = df[df.split == "test"]                       #  2,817 rows
```

Use `val` for model selection and early stopping. **Touch `test` once, at the end.** Picking a model
on the test set reintroduces, by hand, the leakage this whole exercise exists to prevent.

## The leakage this prevents

Rows are (peptide, allele) pairs. A peptide is measured against a median of 4 alleles and up to 36,
and **94% of rows involve a peptide that appears with more than one allele**. Split rows at random
and the same fragment lands in train and test, so the model recognises it rather than predicting it.

So we split by peptide, and group near-duplicate peptides so they travel together.

**Threshold.** The published convention is 80% sequence identity. Every peptide here is a 9-mer, and
for equal-length strings a Levenshtein distance of 1 is reachable only by substitution, so
`identity = (9 − d)/9` gives 0.889 at d=1 and 0.778 at d=2. **80% identity on 9-mers is exactly
"Hamming distance ≤ 1."** Clusters are single-linkage at that threshold, assigned whole.

**This threshold is not load-bearing.** At Hamming ≤1 there are 5,494 clusters from 5,633 peptides
(largest 5); at Hamming ≤2, 5,410 clusters (largest 8). The peptides are mostly far apart, so the
choice barely moves anything and there is no single-linkage chaining problem.

## Two splits, two different questions

| File | Holds out | Answers |
|---|---|---|
| `peptide_split.csv` | **PRIMARY** — whole peptide clusters | Does the model generalise to *new fragments*? |
| `allele_split.csv` | whole alleles | Does it generalise to an *HLA it never saw*? |

The allele split is a secondary analysis, not a replacement. It is the more interesting test of the
brief's actual question — a protein foundation model should beat a one-hot allele encoding precisely
where the allele is unseen, because one-hot cannot represent it at all. Never mix numbers between
the two splits.

## Verification (all run by the script, which fails loudly)

- **0 cross-split neighbours** at Hamming ≤1, checked exhaustively against every training peptide.
- **The detector was validated before being trusted.** A known-positive is planted each run — a
  training peptide with one residue mutated, labelled as test — and the check must flag it. A probe
  that cannot fail is not measuring anything.
- Peptide sets are disjoint, non-empty, and account for all 5,633 peptides.
- All 75 alleles appear in training; no val or test row needs an allele unseen in train.

## Representativeness

| split | rows | % | median t½ | zero fraction | alleles | alleles/peptide |
|---|---|---|---|---|---|---|
| train | 22,532 | 80.00 | 1.10 | 0.203 | 75 | 5.00 |
| val | 2,817 | 10.00 | 1.20 | 0.189 | 72 | 5.02 |
| test | 2,817 | 10.00 | 1.10 | 0.207 | 74 | 4.98 |

That last column was a bug worth recording. The first version ranked splits by **absolute** quota
deficit; since train's quota is 8× the others', it took every large cluster, and test ended up with
no peptide measured against more than 6 alleles while train reached 36 — structurally
unrepresentative even though the row counts were a perfect 80/10/10. Ranking by **fraction of quota
remaining** fixed it. The script now asserts the ratio stays within 0.85–1.15; the buggy version
scored 0.36 and the fixed one 1.00, so the guard separates the two cases rather than merely existing.

## Caveat on the allele split

| split | rows | % | median t½ | alleles |
|---|---|---|---|---|
| train | 22,039 | 78.25 | 1.10 | 64 |
| val | 3,068 | 10.89 | 0.70 | 5 |
| test | 3,059 | 10.86 | 1.30 | 6 |

Alleles are assigned within terciles of their median half-life, which keeps the label distributions
roughly aligned — without stratification, test landed at median 2.90 against train's 0.90. Some
shift remains and is unavoidable: there are only 75 alleles, so an eval split holds 5 or 6, and
alleles genuinely differ in their stability profiles. **Treat allele-split numbers as a
directional signal, not as comparable to peptide-split numbers.**

## Regenerating

```
python scripts/make_splits.py
```

Deterministic given `SEED = 42`. It asserts its own invariants and will fail rather than emit a
leaky split. If you change `CLUSTER_MAX_DIST` or `TARGETS`, you have made a different split — say so
loudly, because every experiment already run becomes incomparable.
